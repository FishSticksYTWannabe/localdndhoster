# Llama 3.1 — 2-bit quantization (guide)

This document explains a practical approach to producing a low-bit quantized Llama-style model and running it locally as an HTTP endpoint your app can call via `ai:generate`.

Important: This guide does not provide model weights. You must obtain Llama 3.1 weights through the correct licensing channel before converting/quantizing.

Overview
- Goal: produce a 2-bit-quantized runnable model (small footprint) for local inference (CPU or GPU), expose a small HTTP server that accepts a prompt and returns text.
- Recommended tooling: `llama.cpp` / `llama.cpp`-based conversion tools, or GPTQ-based quantizers (GGML/gguf + gptq) and a lightweight HTTP server (text-generation-webui, text-generation-inference, or a minimal Flask/Node proxy).

Hardware notes
- 2-bit quantized models are intended for much lower RAM usage but still need memory during inference. A quantized 7B can run on ~8 GB RAM; a 13B/34B still needs more.
- For reliable local use of a Llama 3.1 variant, use a machine with >=16 GB RAM or a GPU with 10+ GB VRAM for larger models.

High-level steps
1. Obtain the original model weights (check licensing).
2. Convert to a `ggml`/`gguf` format if required (tools vary by model provider).
3. Run a quantizer (GPTQ/AWQ/llama.cpp quantize) to produce a 2-bit quantized model file.
4. Run a lightweight HTTP wrapper around `llama.cpp` or text-generation-webui pointing at the quantized model.

Example (using `llama.cpp` + `gguf` workflow)

1) Prepare environment (Linux example):

```bash
# clone llama.cpp (or use a fork that supports your model)
git clone https://github.com/ggerganov/llama.cpp.git
cd llama.cpp
make

# tools/convert might be provided by the model vendor or in companion repos
```

2) Convert model to `gguf`/compatible format (vendor/tooling dependent).

3) Quantize the model (example uses hypothetical `quantize` tool supporting 2-bit):

```bash
# This is an illustrative command. Replace with the quantizer your toolchain provides.
./quantize --input model.gguf --output model.q2.gguf --bits 2
```

4) Run a minimal HTTP wrapper. Example using `text-generation-webui` (which supports gguf and llama.cpp backends):

```bash
# run text-generation-webui in a container or locally and point to the quantized file
# see text-generation-webui docs for exact flags; this is illustrative
python server.py --model /path/to/model.q2.gguf --listen 0.0.0.0 --port 8080
```

5) Point the app to `http://localhost:8080/generate` (or the endpoint your server exposes) — `electron/main.js` already supports calling a local endpoint via `ai:generate`.

Notes and alternatives
- GPTQ/AWQ based quantizers: if you have a PyTorch checkpoint, the community `gptq` tools (or AWQ) can produce 2-bit quantized weights; follow those projects' README for exact commands.
- If you prefer a managed path, use a hosted LLM endpoint and secure it; local quantized models are best for privacy but may require trial-and-error for stable performance.

Safety and licensing
- Verify you have the right to use and quantize the model (Llama 3 licensing terms).
- Do not redistribute model weights without permission.
